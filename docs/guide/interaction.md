# 與 Claude 互動的模式

## 用哪個介面？

| 介面 | 適合做什麼 | 能碰到本機檔案嗎 |
|---|---|---|
| **Claude Desktop → Code 分頁**（Claude Code） | 專案開發、Git、跑指令、部署。**日常主力** | 可以，工作資料夾就是 `D:\01-Project\<專案>` |
| **Claude Desktop → Cowork** | 跨 App 的事務性工作、操作電腦、文件處理 | 可以（授權的資料夾） |
| **claude.ai Chat／Project** | 討論、規劃、寫 PRD、放長篇參考文件（Project 文件 `claude/*.md`） | 不行，除非連到電腦 |
| **終端機 `claude`** | 需要 `/config`、`/permissions`、`/mcp` 這類互動式設定時 | 可以 |

## 標準互動流程（Code 分頁）

1. **選對資料夾**：新對話時把工作目錄設成專案資料夾（例如 `D:\01-Project\35-個人網頁最終版`）。
2. **第一句話就下指令**：`#開工`。Claude 會自己讀 `AGENTS.md`、`PROJECT_STATUS.md`，不用重講背景。
3. **描述目標，而不是步驟**：「幫我加匯出 Excel 的功能，要能選欄位」。Claude 會照 SOP 先快照、再改、再測。
4. **中途存檔**：一段落就說 `#更新`。
5. **結束**：`#收工`。換電腦前一定要做。

## 下指令的寫法

| 情境 | 建議說法 |
|---|---|
| 新功能 | 「加 ___ 功能。驗收標準：___。不要動 ___。」 |
| 修 bug | 「___ 時出現 ___（貼錯誤訊息）。預期是 ___。」 |
| 規劃 | 「先不要寫程式，列出 2–3 個方案與取捨，我選了再做。」 |
| 會重複的事 | 「#SOP」——先把流程做成技能，再執行 |
| 犯過的錯 | 「#學習」——把這次的教訓寫進錯誤知識庫 |
| 改設定 | 「把 ___ 規則改成 ___」，並指明檔案（見 [技能與重要檔案位置](/reference/files)） |

## Claude 會停下來問的時機

其餘動作（改檔、commit、push、部署）都會自動執行並保留回滾方式；只有這些會先問：

- 敏感資料掃描命中（API key、token、身分證字號、手機號碼、人名＋生日／薪資）
- 合併或 rebase 衝突
- 寄信、發訊息、付款、系統設定、把 repo 改成 public
- 分支選擇有歧義

## 回覆風格（來自 AI-PROFILE §3）

- 繁體中文，技術名詞保留英文；先講結論再講理由。
- 規劃時列出替代方案與取捨；完成回報要精簡：做了什麼、結果、需要你決定的事。
- 不確定就直接說不確定。

## 個資（人事資料）

身分證字號、姓名＋生日、薪資、考績、獎懲、請假原因、住址、電話——**必須先在本機去識別化**才給雲端 AI。原始檔放 `data/raw/`（已在 `.gitignore`），對照表只存本機。B 電腦（學校）特別注意。
